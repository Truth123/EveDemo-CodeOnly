## 1. 项目目标

Project EVE Demo 是用于求职作品演示的 Unity 3D 战斗系统项目。

核心目标是制作一套聚焦主角与 Raven 风格 Boss 战斗体验的动作战斗原型，重点展示：

- 第三人称移动、自由视角、锁定视角。
- 玩家状态机和 Light / Heavy 连段。
- Evade / Perfect Evade、Guard / Perfect Guard、Skill。
- HitReaction、Knockdown、Dead。
- Boss AI、Hitbox / Hurtbox、战斗镜头、UI、VFX、SFX。

明确不优先投入：

- 大型开放场景、背包、任务、对话、商店。
- 非战斗向复杂 UI。
- 与 Boss 战求职演示无关的大型系统。

## 4. 当前关键规则

- 状态机通过 `PlayerStateContext` 共享输入、资源、窗口和运行时状态。
- 输入事件先形成快照，攻击、闪避、技能可通过输入缓存跨窗口消费。
- Guard 是即时按下 + Hold 保持语义，不进入普通动作缓存。
- PlayerAttack Phase 只驱动 `CurrentPhase`；Hitbox、InputBuffer、Cancel、Reset、MoveCancel 等功能判断读取 functional clips。
- Combat Timeline 后续不让状态机直接遍历原始 clips；状态类不遍历原始 clips，进入时读取 Provider Data，每帧把 RuntimeSpec Snapshot 转成状态本地 FrameData。缺 Timeline / Reaction / BossAttack 不再补硬编码默认玩法数据。
- Provider Data / RuntimeSpec 在 Provider 中缓存；运行时不自动监听资产改动，编辑期改动通过 `Refresh Runtime` 手动应用。
- Combat Timeline Editor 的 `Follow Runtime` 是只读观察工具：Player / Boss 暴露当前 Timeline `ActionId + ElapsedTime` 快照，Editor 只在选中资产匹配时移动 playhead，不参与运行时决策。
- Combat Timeline 的全局 `Duration / Total Frames / Frame Rate` 是采样模型，不是 clip 重采样命令；clip 的秒级 `StartTime / EndTime` 是窗口事实，帧号显示随当前 `FrameRate` 即时换算。
- Reaction 资产级数据只有 Reaction 类型；timing、Player Motion、动画预览分别来自 Reaction、Motion、Animation Preview Track。不要再在 `CombatReactionTimelineAsset` 上恢复资产级 direction、timing、motion 或 preview fallback 字段。
- 2026-06-24 PlayerSkill 已移除 `PlayerSkillState.CurrentSkillCost` 静态入口，改由 `PlayerSkillActionResolver` 统一解析 Skill1 Provider Data；Skill 状态内部只读取 `currentSkill.SkillCost`。`PlayerAttackState` / `PlayerSkillState` 热路径已收敛为 Tick 内单次 `EvaluateFrame`，再把状态本地 FrameData 传给窗口、缓存和取消派生 helper。
- 2026-06-24 Guard Timeline / PerfectGuard Chain 语义已修正：GuardHit / PerfectGuardReaction 是 Guard 内部 Marker 时长，`Input_PerfectGuardChain` 是重按输入窗口，ChainActive 由 Guard 状态运行时动态打开；旧 `Player_GuardHit` Reaction Timeline 已删除。`CombatTimelineEditorWindow` 的多 Animation Preview 播放优先级已改为选中 clip > 最近成功播放 clip > 当前可见顶层 clip。
- Player Dead 不属于可恢复 Reaction 节奏；不要给 `Reaction_Player_Dead.asset` 添加 Recovery / CanReturn / Cancel 窗口来满足普通受击校验。
- Player HitReaction 的 Phase 只做动画 / 调试展示；受击恢复转动作许可必须来自 Cancel capability，攻击恢复复用 `Cancel_AttackReset`。
- Player Knockdown 的 Phase 只做动画 / 调试展示；起身动作许可必须来自 Cancel capability，攻击起身复用 `Cancel_AttackReset`。
- Player HitReaction / Knockdown 连续刷新时，状态计时和动画重播是两条路径：状态由同状态 `TransitionTo` 重置，动画由 `CombatReactionAnimationRequestVersion` 触发重新 CrossFade；不要只用 Animator state hash 判断是否跳过受击重播。
- Player HitReaction / Knockdown / Dead 动画入口只允许由 `PlayerAnimationBridge` 代码 CrossFade 触发；不要在 Base Layer 恢复指向 Reaction 状态的 `AnyState` 兜底连线。
- GuardHit、PerfectGuard 和 GuardRelease 的窗口必须按 Guard 内部轨道隔离解析：前两个反应轨道各自只读取 `Cancel_ToGuardRelease`，GuardRelease 独占动作 Buffer / Cancel；禁止用全局 Guard RuntimeSpec 的同名 capability 混读阶段。
- GuardHit 后所有动作派生及连续精防都必须经过真实 GuardRelease：窗口前松开不会打断 GuardHit；同帧 Evade / Skill 只转存到 Release Buffer，同帧 Attack 忽略；PerfectGuardChain 仍只在 PerfectGuard 反应中由 `Input_PerfectGuardChain + GuardPressed` 打开。
- Lock-on 目标是朝向参考，不是全状态强制转向：Player 非承诺状态可持续面向 Boss，但 `Attack / Skill / Evade / GuardHit / PerfectGuard / HitReaction / Knockdown / Dead` 不被通用锁定朝向覆盖；Boss `Attack / Recovery / HitStagger / Knockdown` 不由 Actor 级通用朝向追踪玩家。
- HitNode 运行时详情统一为 `CombatHitNodeData`；Snapshot 只返回 `ActiveHitNodeIds`；Boss attack BoxCollider / anchor 只负责检测体来源。
- Boss MotionWarp 配置由 `BossMotionWarpProfile` 维护；Boss 位移模式、出招距离范围、空间预筛选和 Warp / CodeMove 参数不再复制到 `BossAttackDefinition` 或 `BossAttackTimelineAsset`。
- Boss MotionWarp 的 `StopDistance` 只服务远距离接近停靠；当玩家已经小于 `StopDistance` 时，`ToAttackPoint` 窗口退化为原地 / 极小修正，不允许把攻击落点算到 Boss 身后。Boss 攻击期 facing target 独立于 landing target，避免朝 StopDistance 落点侧向扭头。
- Boss Orbit 位移不使用 `StopDistance` 表达半径；`OrbitAroundTarget` 在窗口开始时锁定当前 Boss-玩家水平距离作为半径，按 `OrbitAngleDegrees` 旋转，`MaxMoveDistance` 不裁剪 Orbit 总位移。
- Boss 命中去重粒度为 `AttackInstanceId + HitNodeId + Target`；Target 优先取 `CombatHurtbox`，缺 Hurtbox 时取 `PlayerCombatReceiver`。
- Boss 当前唯一正式入口是 `BossActor`；不要新增或恢复 `BossController` facade。
- Boss 状态机当前只保存 `BossStateId` 与状态计时；Actor、Blackboard、Brain、动画、移动和反应系统共享该唯一状态事实，不得恢复顶层分类或子模式镜像。普通中立状态只有 `Approach / Strafe`。
- Boss 普通攻击动作池来自 `BossActionSet`；新增普通招式应补 Timeline、MotionWarpProfile、ActionSet 和动画绑定，不改 Brain / Runner / Combat 框架。
- Boss 攻击选择的战术标签来自 `BossActionSet.tags`，标签常量集中在 `BossActionTags`；标签只影响合格候选之间的 Utility，不替代 MotionProfile SelectionProfile。
- Boss 非承诺状态战术节奏由 `BossBrain.Decide()` 决定；`BossStateMachine` 只保存状态事实、计时和已承诺动作 / 反应生命周期。普通中立只有 Approach/Strafe，至少持续 `0.3s`，中距离固定 `1:1`，强制中立期间不检查攻击池。
- Boss 短期决策记忆只存在于 `BossActor` 的 `BossDecisionMemory`；Brain/Selector 不持有或修改 memory，只读取 Actor 组装的输入。动作冷却与选择历史、主动压力与受击预算、玩家行为统计共享所有者但保留独立清理边界。旧 Strafe forced attack retry 已删除，不得恢复绕过 ActionSet/Selector 的硬编码攻击。
- Boss 可读取玩家已经进入的公开状态和短期历史作为选招评分输入，但不得读取当前帧原始输入。玩家战术快照只保留当前状态/持续时间、频繁防御和持续后退；低 HP、受击返回和最近 Perfect 收益镜像已删除。Selector 在全部正分合格候选内按动作池和池内权重随机，不截断 Top 3。
- Boss Reaction 位移只通过 Reaction Timeline 的 `BossCodeMove` 引用 `BossMotionWarpProfile` action/window；Timeline 不复制完整位移参数，缺引用或缺 MotionProfile 配置时仍进入反应状态但不执行位移。
- Boss 是否进入受击反应只看当前状态 Timeline 的 `BossReactionGateWindow` 与 Resolver 输出的 `CombatHitOutcome`；伤害结算仍由 Hurtbox / Resolver 完成。`AllowInterrupt` 表达开放反应，`BlockInterrupt` 表达同时间段阻止特定结果，当前 Block 首版用于 Skill Knockdown。`CombatAttackType` 在 Boss 受击侧统一使用玩家攻击来源语义：`LightAttack / HeavyAttack / SkillAttack`。不要恢复旧 `CombatInterruptWindowClip` 或 `SkillInterruptArmor` gate 路径。
- BossAttack / BossReaction Timeline 不再配置 Armor 轨；Raven Boss 资产中的空 `Skill Armor` 轨已删除。Boss 受击门控统一放在 `Boss Gate` 轨，`Armor_SuperArmor / Armor_Uninterruptible` 只保留给非 Boss gate 的通用 / Player 动作能力。
- Boss HitStagger 普通刷新还受 Actor 侧连续受击预算限制；`BossReactionGateWindow` 允许刷新不代表可以无限刷新，预算耗尽后普通 HitReaction 只扣血，让 Boss 到达 `Reaction_CanReturn` 起点并交给 Brain 处理压力响应。StateMachine 不直接兜底切 Strafe，受击动画回 Idle 只影响视觉。
- Boss 受击反应的状态提交规则保留在 `BossActor`：Dead 切换状态并播放状态动画，同反应状态只刷新 `StateElapsed`，其他反应状态切换但不播放默认状态动画；`RejectReason` 只作为观测信息。
- Boss 状态切换理由必须在 `BossActor` 的请求层显式表达；生产代码不得从普通 Tick、Brain、Reaction 或 Action 分支直接绕过请求层调用最低层 `CommitStateTransition()`。
- Combat Feedback 是表现层：HitStop / CameraShake / VFX / SFX 不反向驱动伤害、资源、状态切换或输入窗口；CameraShake 由 feedback profile 显式选择，不是所有命中默认触发。
- 攻击出手剑光和命中接触反馈分离：Player 武器拖尾当前由手动新增的 `SlashTrailVFX` / 场景资产表现承担，Player 状态机不再运行时生成旧拖尾或弧光；Boss 持续拖尾由 `BossAttackExecutor` 按 HitNode SourcePart 直接驱动唯一武器与左右小腿的固定 `SlashTrailVFX`，Boss 直刺由 `BossHitNodeParticleVfxController` 播放独立粒子；`CombatFeedbackPlayer` 只消费真实命中后的 `CombatFeedbackEvent` 处理 HitStop、CameraShake、接触 VFX / SFX、Boss 命中亮度 pulse 与 PerfectEvade 子弹时间。
- Player 武器拖尾是纯表现资产，不作为攻击 HitNode、取消窗口或输入缓存的数据来源；后续如果正式武器资产新增专门 Socket / Bone，优先在场景 / Prefab 里调整 `SlashTrailVFX` 采样点。
- PerfectEvade 反馈是规避奖励语义：不复用命中 HitStop 卡肉，只通过反馈时间缩放控制器请求短子弹时间；后续红色线条、残影、短拖尾属于 VFX 阶段。
- PerfectGuard V1 是接触防御成功语义：无 HP / GuardDamage，奖励 BetaEnergy 15，默认 HitStop `0.06s` / TimeScale `0.06`、CameraShake `0.075 / 0.12s / 34Hz`，播放白金正式接触爆发 `FX_Feedback_PerfectGuard_Stellar.prefab` 和 `Assets/Audio/hit_perfect.mp3`；Boss 是否进入 PerfectGuardStagger 只由 Boss HitNode `TriggersPerfectGuardBossStagger` 决定。
- 黄光不可格挡攻击不属于新 Combat 类型：HitNode 通过 `CanBeGuarded=false / CanBePerfectGuarded=false / CanBePerfectEvaded=true` 表达，只能闪避 / PerfectEvade，不能 Guard / PerfectGuard，不奖励 PerfectGuard BetaEnergy，不播放 PerfectGuard VFX / SFX，也不触发 Boss PerfectGuardStagger。
- 复杂计划提交前必须做语义审计：先按玩法语义分类并列出不应触发 / 不应复用的反例，再判断复用、合并、优先级或底层技术仲裁。
- 高频功能目录已新增局部 `AGENTS.md`：Combat、Combat/Timeline、Player/StateMachine、Boss。修改这些目录前必须先读取对应局部规则。
