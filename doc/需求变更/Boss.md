# Boss 需求变更

更新时间：2026-09-11

## 活跃规则

- Boss Detached 相关 PlayMode 测试创建的临时 Component 必须在收尾时连同所属 GameObject 一起销毁，不能只移除 `BossDetachedHitVolume` 而留下 Collider、Rigidbody 或 Transform；测试实例也不得保存进 `Demo.unity`。反例：将生成的 `BossDetachedHitVolume` 直接传给只执行 `DestroyImmediate(component)` 的通用清理逻辑，会留下启用的非 Trigger Collider 并在场景中形成隐藏阻挡。
- `BossStateId` 是 Boss 状态机、Actor、Blackboard、Brain、动画、移动与反应系统的唯一状态事实源。不得缓存或传递可由它确定性推导的 `BossHfsmStateId / CurrentTopState / RepositionMode / ActionPhase / ReactionMode` 镜像；Brain 直接按 `BossStateId` 判断 Action、Recovery、Reaction 与 Approach/Strafe 分支。反例：不得为了简化一次条件判断而重新给 Blackboard 同时传入具体状态和顶层分类状态。
- `BossMotionController` 只保留底层位移执行所需状态，不得常驻保存每帧 RootMotion、CodeMove、Warp、碰撞、Orbit、Gizmo 或选招拒绝原因等调试遥测，也不提供 `LastSelectionRejectReason` 或带 `out rejectReason` 的重复预筛选 API。正式 AI 预筛选只返回 bool；缺失关键 MotionProfile/action config 时仍必须拒绝动作，实际启动路径保留明确配置错误。反例：不得为了测试或 UI 再把 `LastCodeMoveDelta`、`CurrentWarpWindowName` 等镜像状态加回执行器。
- Windows Direct3D 12 构建不得再让 Raven 主体依赖 `Project EVE/Raven Body Overlay` 的不兼容 Forward Pass。七个主体材质必须直接使用官方 `Universal Render Pipeline/Lit`；BodyColor/HairColor 必须由独立同网格、同 RootBone、同骨骼顺序的覆盖 SkinnedMeshRenderer 绘制，并通过每材质槽 PropertyBlock 写入简单透明覆盖 Shader。覆盖层必须 `ZTest Equal / ZWrite Off`、不投射阴影、颜色 Alpha 为零时关闭，HairColor 仍只作用于槽 5/6。Visibility=0 必须关闭主体与覆盖层，武器/IdleGlow 继续支持中间值淡出；不再要求身体中间 Visibility 的 Bayer 裁剪。反例：不得把旧自定义 Shader 重新指定给主体材质，也不得用 Always Included Shaders、运行时 `Shader.Find` 或材质实例化规避兼容问题。
- Demo 标题阶段 Boss AI 必须保持停止；只有开场镜头到达战斗位姿后才调用 `StartBossAiWithInitialAttackCooldowns()`。启动时所有启用的 Attack 必须从各自 Combat Timeline 的正式 Cooldown 开始倒计时，不能提交最近选择或重复历史；Reposition、Approach、Strafe 不得被这批初始攻击冷却阻塞。反例：点击开始后的镜头过渡中，Boss 不得转向、接近或起手攻击。
- `ShieldBreakStun` 的持续阶段必须包含可独立禁用的 `FX_Boss_StaggerOrbit3D` 补充层，并由现有 `BossShieldBreakStunVfxController` 与其他 `StunLoop` 子粒子一起管理。该层固定使用一个头顶水平旋涡环和三颗同步公转星点，统一约 `1.2s/圈`，不允许恢复左右月牙横铺、多旋涡持续发射、三向交叉面或各元素不同步慢转。它只负责 Raven 头部周围的世界空间视觉，不得成为进入眩晕、维持 6 秒计时、切换 Weak 动画或恢复护盾的条件；缺失或停播时 Boss 状态机与结算必须不受影响。
- Boss 独立防御护盾最后一格被 PerfectGuard 清零时，必须在该次结算同帧停止当前 Action、Recovery、剩余 HitNode、攻击位移与后续连段，直接进入 `ShieldBreakStun` 并播放 `Result_Hit_JustParry`；6 秒状态计时和破盾 VFX 同帧开始。该规则高于 `TriggersPerfectGuardBossStagger`，因此非末击或未勾选该标志的 HitNode 破盾也必须触发。状态经过 `0.8s` 时只切换一次 `Result_ShieldBreak_Stun / Result_Weak_S`，不得等待原攻击 Recovery 或交回 Brain；`5.3s` 启动恢复预警，`6.0s` 自然结束并回满护盾。普通未破盾 PG 仍只有带标志的 HitNode 才触发短 HitStagger；长眩晕中普通受击只扣血且不刷新计时，只有 `SkillAttack + Knockdown` 可提前中断，死亡不回满。反例：未破盾且 HitNode 未勾选 PG Stagger 时不得播放 JustParry 或进入长眩晕。
- Boss HP 首次进入 Phase2（`≤60%`）与 Desperation（`≤25%`）时必须各固定释放一次 `Raven_BurstAreaSlash`。阶段变化发生在当前 Attack、Recovery 或 Reaction 内时不得直接打断现有生命周期，而应排队到首个安全 Brain 帧并优先于普通选招启动；该固定路径不受随机权重、近期使用、压力筛选或已有冷却阻止，但必须继续复用启用的 ActionSet 条目、Combat Timeline、ActionRunner、MotionProfile、HitNode 以及正式压力/冷却/后续中立提交。死亡不触发、同一阶段不得重复；若一次伤害跨过两条阶段阈值，两次转换请求都必须保留并在安全边界依次执行。反例：处于尚未结束的普通攻击或 ShieldBreakStun 时，阶段请求只能等待，不能立刻覆盖当前动画和判定。
- 护盾击破视觉只允许在正式 `ShieldBreakStun` 状态进入时启动；由于当前已无前置 HitStagger，它必须与破盾结算及 `Result_Hit_JustParry` 初始动画同帧开始。离开该状态时必须立即停止并清空，恢复预警固定从 6 秒状态的最后 `0.7s` 开始。表现控制器不得修改护盾回满、状态优先级、AI、伤害、Timeline、HitNode 或动画播放。
- `Raven_BurstAreaSlash/BurstAreaSlash_1` 必须使用 Boss 根为中心的单次 `InstantPulse` 球形查询；其查询层和 NonAlloc 容量必须继承 `BossAttackExecutor`，禁止在 Emitter 内硬编码 Everything 或容量 `4`。用户实战确认的当前有效半径为 `9.3m`，Demo 的单位 SphereCollider 绑定缩放与 Timeline `EffectiveRange` 必须同时保持 `9.3m`。外观粒子不得反向驱动命中；`BurstAreaSlash_3` 保持独立结算。
- `M_Raven_BurstAreaSlashEnd` 的空中段必须保持原起跳、最高点、命中与总时长节奏，仅允许通过 `Root/Bip001.m_LocalPosition.x`（本地 `-X` 对应世界 `+Y`）把相对起跳位置的世界净升高提高到当前 `4.50m`。新增高度必须在 `BurstAreaSlash_3` 开始对应的 Clip Local Time `2.666667s` 前归零；不得修改 Bip001 的 Y/Z、旋转、缩放、其他骨骼、Root 曲线、Animator Controller、Timeline、HitNode、MotionWarp 或动画事件。
- 线性剑气的 `BossDetachedHitVolume` 必须启用，以执行生成瞬间锁定的世界空间速度和 `2.2s` 生命周期；当前 SwordAuraCombo 三条为 `18m/s`，EvadeBackSwordAura 为 `20m/s`。禁用视觉模板不影响判定体飞行与命中。
- SwordAuraCombo 三条与 EvadeBackSwordAura 一条 Detached 必须共享 Demo 场景 `Boss/FX_Boss_RangedSwordAura_SwordSlash6` 作为可编辑视觉模板，`BossDetachedLinearHit.prefab` 只保留 Collider、Rigidbody 和命中组件。模板运行时隐藏，每次发射克隆必须继承当前本地 TRS 并从头播放粒子。根剑气、Slashes、Slashes2 保持 `0.3s` 短寿命，Pivot 存续 `2.2s` 并按距离生成接力刀幕；四条绑定均以 Pivot 为 `VisualTravelDriver`，视觉保持世界空间且按绑定 `Speed` 换算粒子本地速度。每条绑定可独立设置 `LocalEulerAngles.z`，该值只在模板基础旋转上追加视觉/BoxCollider 滚转，不改变直线飞行方向。BurstAreaSlash 不绑定该模板。
- `Raven_SlashCombo` 开场红光表示后续连续猛攻可 Guard / PerfectGuard：按用户最终动画调参，Clip Local Time `0s` 触发 `OnRedAttackParticleStart`。红色只能由胸口红点与 `BossBodyColorController.hairColor` 提供，HairColor 只写 Raven 头发材质槽 5/6；不得再用全身 BodyColor 染红皮肤、服装、头部或武器，Visibility 保持 1。前四个 HitNode 的防御语义不得改变；最终 `SlashCombo_YellowIai` 继续不可 Guard、不可 PerfectGuard、可 PerfectEvade。红光只属于提示表现，不得反向修改 Timeline、伤害、AI、MotionWarp、Recovery 或冷却。
- Dead 是 Boss 最高优先级且不可返回的终止状态。`BossAnimationBridge.PlayState(Dead)` 必须独立、强制从头播放 Raven Base Layer 的 `CH_P_EVE_51|Eve_Stand_Dead2`，不得复用 Idle/Recovery；`Reaction_Boss_Dead` 的运行时与预览 Animator 状态名必须一致，死亡预览不得循环。
- Skill1 Hit1/Hit2 的 `SkillAttack + HitReaction` 在 Reaction Gate 允许时进入或刷新 HitStagger；第二段必须重播动画并重置计时。最近一次为该结果时 `CanReturnFromReaction` 至少等待 `0.95s`，期间不交回 Brain，但 Boss 始终可受伤且 Skill 刷新不消耗普通攻击受击预算。Hit3 保持 Knockdown；显式 Block Skill、既有 Knockdown、ShieldBreakStun 和 Dead 边界不得被绕过。
- Boss 拥有 `BossActor` 独立维护的 15 格防御护盾，只由正式 PerfectGuard 每次扣 1 格。最后一格归零后的同一帧直接进入 6 秒 `ShieldBreakStun` 并先播放 `Result_Hit_JustParry`，`0.8s` 后在同一状态内切换 Weak 动画；不再存在独立 HitStagger 引导，也不读取被打断攻击的 Recovery 作为进入门槛。长眩晕期间普通命中不得刷新或退出，只有 `SkillAttack + Knockdown` 可提前转入现有 Knockdown。自然结束或起身回满，死亡不回满，目标丢失/停止 AI 等异常退出回满。
- Raven Animator 的 `Result_ShieldBreak_Stun` 使用 `CH_M_NA_53_Preview|Result_Weak_S` Motion，状态速度为 `2.5`、无自动退出并保持末帧；状态播放、退出和回满由 BossActor/ReactionSystem/HFSM 统一驱动。
- `Raven_ChaseGrab` 的黄色 BodyColor 只允许在作者配置的黄光 cue 时段内播放；`Raven_SlashCombo` 开场使用红色连续猛攻提示，最终 YellowIai 保留不可防玩法语义。所有提示期间 `visibility` 始终保持 1，其他 RavenAuthored 动作不得继承覆盖。Demo Boss 必须由 `BossAttackCueVfxController` 显式绑定独立 Yellow/Red 根，粒子只由对应 Clip 的 Animation Event 触发，不再由 `BossAttackExecutor` 按 AttackId + elapsed 判断；事件不得反向接入战斗逻辑。
- Boss Attack 冷却起点固定为 `AttackStartTime + LastHitNodeEndTime`，下一次冷却截止为该起点再加 Timeline `Cooldown`；实际重新选招仍需同时等到 `FinalRecoveryEndTime`。Reposition 无 HitNode，继续从 Action 起手计算冷却。只有 Runner 成功启动后才提交冷却和重复计数，失败启动不消耗二者。
- `BossAnimationBridge` 的代码状态播放必须使用固定秒数 `CrossFadeInFixedTime`：Idle 为 `0.20s`，其他状态默认读取 Inspector 的 `0.08s`；不得把这些数值作为归一化动画比例。Animator Controller 内部转场、动作 Clip 与 Root Motion 权限不受影响。
- Raven Animator 必须保持 `Update Mode=Normal / Animate Physics=false / Apply Root Motion=false`；运行时不得调用 `Animator.Update / Rebind`、切换 `Animator.applyRootMotion` 或改走 FixedUpdate 位移。14 个 Raven 动作必须使用 `Assets/Animator/RavenAuthored/` 下的单 Clip，由 Base Layer 同时播放骨骼、Root Motion、`bodyColor.r/g/b/a`、`visibility` 与 Animation Event；SlashCombo 还必须在同一 Clip 播放 `hairColor.r/g/b/a`。不得恢复 BodyColor 同步 Override 层、NoRoot Mask 或独立运行时采样。Animator delta 仅由 `OnAnimatorMove` 提取，正式应用仅允许 `BossMovementLayer.Action + RootMotionWarped`，其他层级或位移模式必须忽略。
- Raven 身体颜色由 Animator 根的 `BossBodyColorController` 驱动：`bodyColor` 通过独立覆盖 Renderer 在七槽按 HDR RGB 与 Alpha 混合，`hairColor` 作为上层覆盖只允许作用于槽 5/6 的 Hair02/Hair01。主体材质保持官方 URP Lit 的原始 Opaque / TransparentCutout 与 ZWrite，不修改 `_BaseColor`；覆盖 Renderer 使用同一网格与骨骼并只写 `_OverlayColor`。独立 `visibility` 不复用颜色 Alpha：零值关闭主体与覆盖，武器和 `FX_BossWeaponIdleGlow` 保留连续淡出。MoveChainCombo、MoveCombo、RapidMoveBack 保留原人工表现曲线和事件；ChaseGrab 使用黄色全身前摇，SlashCombo 开场仅使用红色头发提示；其余合并动作保持中性表现。迁移不得覆盖已验证的合并 Clip，且拖尾、Detached、粒子、HitNode、伤害和 Boss AI 不受影响。
- SwordAuraCombo 与 EvadeBackSwordAura 的远程剑气使用“发射前分段追踪、生成后直线锁定”：只在 MotionProfile 的零位移 `FaceTarget` 窗口内以 `720°/s` 跟踪玩家，HitNode 首帧按 Boss 当时水平正前方生成 Detached；其他攻击、已生成剑气和 Recovery 不获得全局追踪。EvadeBackSwordAura 保留 `RootMotionWarped` 动画后撤。
- Boss AI 调试显示只读正式运行时事实：压力、最近动作和冷却统一来自 Actor 独占的 `BossDecisionMemory`，动作池由最近 `ActionId` 回查 `BossActionSet`；禁止为 UI 复制或反推第二套选招状态。
- Boss 正向命中加压按当前 `AttackInstanceId` 聚合并即时补差：HitReaction 累计上限 `+4`，Knockdown / Dead 累计上限 `+10`；旧实例迟到结果不得影响新攻击的压力、PG/PE 减压或恢复奖励。
- 当前自然减压为 Idle / Strafe / RapidMoveBack `-10/秒`、Approach / HitStagger `-6/秒`、Recovery `-8/秒`、Knockdown `-10/秒`；Attack 为 `0/秒`，玩家处于 HitReaction / Knockdown 时暂停所有自然减压。
- Raven 三个 Critical 攻击中，`BetaChargeCombo` 的压力成本为 `24`，`SlashCombo / BurstAreaSlash` 保持 `30`；ActionSet 资产与内容迁移源必须保持一致。
- Boss Brain 入口不承担 Recovery / HitStagger / HitJustParry 奖励锁判断；进入 Brain 即表示生命周期系统已经允许战术决策。
- HitStagger 可返回后走统一三层决策。原“逃脱评分”正式命名为“受击反制评分”：评分通过后，HitEscapePool、后撤反击、近身反击以及其他 ActionSet 未禁止受击上下文的动作池共同参与候选；评分未通过时本次不启动动作候选，按普通中立规则选择 Approach 或 Strafe。
- 降压模式禁止启动所有 `BossActionKind.Attack`。HitEscapePool 的 `BossActionKind.Reposition` 可在降压模式绕过 HitStagger 上下文要求，但仍必须通过 Enabled、阶段、距离、冷却、MotionProfile、空间预筛选和最近使用限制；不可选时回退 Approach / Strafe。
- `MustEnterNeutral`、玩家仍 Knockdown、当前压力达到阶段硬上限或连续攻击达到阶段上限时，仍在动作池检查前优先执行普通中立；条件解除后才尝试降压 Reposition。
- `BossBrain / BossActionSelector` 的降压模式只读取 `BossDecisionMemory.PressureDecayMode` 写入的 `BossBrainDecisionInput.PressureDecayMode`；该值使用阶段进入/退出阈值滞回，不允许在 Brain 或 Selector 内用 `TempoPressure >= EnterDecayPressure` 瞬时重算。
- `BossActor.TickRuntime` 通过单一 `UpdateDecisionMemory` 每帧只解析一次玩家状态，依次更新玩家行为、压力衰减和降压模式并创建一次 `BossPlayerTacticalSnapshot`；同一快照继续用于压力衰减、Recovery 结束后的 Brain 评估和 `BossBrainDecisionInput`。快照是当前帧不可变事实，不并入跨帧 `BossDecisionMemory`。
- Boss Attack 与 Reposition 共用 `BossStateId.Action = 5` 及 `BossActionRunner.StartAction / Tick / EndAction`；动作类型必须来自显式 `BossActionKind`。Attack 必须有 HitNode，Reposition 必须无 HitNode 且配置 `MustStrafe`，错误配置拒绝启动。
- RapidMoveBack 不创建 AttackInstance、不提交 70%/30% 攻击压力、不增加连续攻击次数；成功启动时一次性减压 `20`，执行期间继续按 `-10/秒` 衰减，结束后进入至少 `0.3s` Strafe。启动失败不减压，成功后被打断不返还，降压模式由下一次正式模式更新按退出阈值关闭。
- Raven 当前正式目录为 13 个动作；新增 5 招均保持 enabled。`BetaChargeCombo / SwordAuraCombo / EvadeBackSwordAura` 的 P1 权重继续为 0，不能通过本轮出现率校准提前进入 Phase1，也不能绕过压力、上下文或空间硬过滤。
- Boss 正式攻击命中同时支持骨骼 `BossAttackHitboxAnchor` 与世界空间 Detached 判定体，两者统一复用 `BossCombatSystem`。
- Boss Recovery 只追踪当前攻击；不保存或遍历历史攻击恢复 Tracker。Detached 的 `AttackInstanceId` 只继续服务命中去重，上一攻击不得在下一攻击开始后补写正确破解奖励。
- Boss 对玩家造成伤害以 `PlayerCombatReceiver` 为必要条件；`CombatHurtbox` 是可选命中框来源，存在时用于更细去重，缺失时按 Receiver 去重。
- Boss 位移统一由 `BossMotionController` 执行，最终通过 `CharacterController.Move()`。
- Boss 出招距离范围统一由 `BossMotionWarpProfile` 的 SelectionProfile 维护；缺 Profile 或缺 attack config 时拒绝选择该招式，不创建运行时默认配置。
- Boss 攻击位移模式也统一由 `BossMotionWarpProfile.BossAttackMotionConfig.MotionMode` 维护；`BossAttackTimelineAsset` 和 `BossAttackDefinition` 不再保存 motion mode 或 selection 镜像字段。
- RootMotionWarped 使用窗口级 Root Motion 预算。
- PerfectGuard 可按 HitNode 配置触发 Boss 反制硬直。
- Skill 击倒和 Boss 攻击中断必须正确结束当前攻击和位移上下文。
- BossAttack Timeline 运行时定义通过 RuntimeSpec 解析统一 `CombatHitNodeData[]` 和 `BossReactionGateWindow`；BossActor 只消费 `EvaluateBossReactionGate()` 返回的 `BossReactionGateResult`，旧 `SkillInterruptArmor` Snapshot 和 `CanBeInterruptedBy()` Boss gate 路径已删除。
- Boss 非承诺状态的短期战术记忆由 `BossActor` 持有；`BossBrain` 只读 `BossBrainDecisionInput`，不直接读配置、不修改 memory、不驱动移动或攻击。
- Boss 攻击选择可读取 `BossActionSet.tags` 作为战术角色标签；标签只影响合格候选之间的 Utility 分数，不绕过冷却、角度、MotionProfile 距离或空间预筛选。
- Boss 主动进攻节奏由 `BossActionSetEntry`、阶段压力配置和 `BossDecisionMemory` 表达；ActionSet 是池、P1/P2/P3 权重、压力、偏好与后续策略的唯一来源，Attack 压力按 70%/30% 提交并自然衰减。
- Boss 玩家战术快照只保存正式决策消费的玩家可见事实：当前顶层状态与持续时间、频繁防御和持续后退。它不复制玩家 HP、受击返回记录、PerfectGuard/PerfectEvade 收益、Guard/Evade 逐帧窗口、未配置偏好的频繁闪避或 Attack/Skill 承诺派生字段；不得读取当前帧原始输入或按键。
- Boss 选招使用三层决策：先判断攻击/中立，再选择动作池，最后在池内硬过滤与加权随机；不再截断为 Top 3。
- 玩家低 HP、刚从 HitReaction / Knockdown 返回或刚 PerfectGuard / PerfectEvade 成功不参与 Brain/Selector 选招；进入 Brain 后只按《Boss AI 方案设计》的强制中立、动作池硬过滤、压力硬上限和权重偏好选择。Perfect 防御产生的恢复奖励仍由 `BossAttackRecoveryTracker` 约束 Recovery 截止时间，不复制到玩家战术快照。
- Boss `HitStagger / Knockdown` 的受击位移可由 Boss Reaction Timeline 上的 `BossCodeMove` clip 声明，并统一引用 `BossMotionWarpProfile` 中的 action/window；Reaction 位移只改变 CodeMove 节奏，不改变受击生命周期、HitNode、AI 决策或 Dead 规则。
- Boss 被玩家攻击是否进入反应只读取当前状态 Timeline 的 `BossReactionGateWindow`；`Attack / HitStagger / Knockdown` 未开放对应 `CombatAttackType` 时只扣血不刷新反应状态，Block gate 可优先拒绝指定命中结果，Dead 仍最高优先级。
- Boss HitStagger 的初次命中计入连续受击预算，一轮最多 3 次；每次硬直允许返回时按 25%/60%/100% 受击反制评分决定是否允许反制动作候选，正确破解奖励窗口内禁止受击反制决策。
- `CombatAttackType` 在 Boss 受击语义中统一使用玩家攻击来源：`LightAttack / HeavyAttack / SkillAttack`。击倒等效果由 `CombatReactionIntent` 和 `CombatHitOutcome` 表达，不新增 Boss 专属攻击类型。
- BossReactionSystem 只消费 `CombatHitOutcome` 与 `BossReactionGateResult`；`DamageOnly / GuardHit / PerfectGuard / PerfectEvade / None / IgnoredByInvincible` 不进入 Boss 反应，`HitReaction / Knockdown` 才会检查 gate 并提交反应。
- Boss 反应状态提交规则由 `BossActor` 直接根据 `BossReactionExecutionPlan.TargetState` 内联处理；`BossReactionSystem` 不再提供单独的 StateCommitPlan，`RejectReason` 只作为最近命中观测信息和测试断言信息。
- Boss 状态切换请求由 `BossActor` 内部统一仲裁。启动 / 停止、Tick 安全检查、Brain 战术、Action 完成、Knockdown 阶段和 Reaction 计划都必须先提交显式 `BossStateTransitionReason`；最低层 `CommitStateTransition()` 只作为 `BossActor` 内部执行状态事实更新和副作用的提交函数。
- Boss HitStagger 到 `Reaction_CanReturn` 起点后可让 `BossBrain.Decide()` 接管下一步攻击或 Approach/Strafe；StateMachine 不再按反应总时长兜底切 Strafe，受击动画自动回 Idle 也不改变 `BossStateId.HitStagger`。
- Boss 连续受击达到压力上限后，`BossBrain.Decide()` 在 HitStagger `CanReturn` 时优先按 ActionSet 标签选择 `DisengageCounter / CloseCombo / GapCloseCombo` 反制；没有合格动作时按普通中立规则选择 Approach/Strafe，不恢复普通 Retreat。
- Boss 的 Action / Reaction 专用结束方法只清理对应移动层。Boss 从 `HitStagger / Knockdown` 退出时只结束旧 Reaction 位移层；若压力响应或其他流程已先启动 Attack 并建立 Action 位移层，不允许再用全局 `StopAllMotion()` 清掉该攻击位移上下文。
- Lock-on 转向 V1 保持状态层 + 动作窗口层组合：Boss 的 `Idle / Approach / Strafe` 由 `BossActor.RotateToTarget()` 面向玩家，攻击期只由 MotionWarp / RootMotion 窗口有限追踪，Active / Recovery 不做全局吸附转身。
- Boss / Player 身体占位规则固定：Boss 攻击、后撤、突进等动作位移不被玩家 target 身体硬阻挡，运行时只忽略当前目标的非 trigger 身体 Collider；环境仍是硬阻挡，玩家侧软互斥负责维护最低身体距离。
- `StopDistance` 只表示 Boss 从远处接近玩家时的停靠距离；玩家已经过近时 `ToAttackPoint` 不生成 Boss 身后的反向落点。Boss 攻击期朝向目标与位移落点分离，避免朝 stop point 侧向扭头。
- `OrbitAroundTarget` 不读取 `StopDistance` 或 `MaxMoveDistance` 作为半径 / 距离预算；Orbit 半径由窗口开始时 Boss 到玩家的当前水平距离锁定，`OrbitAngleDegrees` 控制左 / 右旋转角度，当前 Raven Orbit 默认为 90 度。
- Boss 持续拖尾默认由 HitNode `SourcePart` 选择：`Weapon` 固定使用唯一 `RavenMonster_Weapon/SlashTrailVFX`，`LeftFoot / RightFoot` 固定使用 Boss 对应 `Ab-L-Calf-Tw1 / Ab-R-Calf-Tw1` 下的 `SlashTrailVFX`；其他 SourcePart 不触发固定拖尾。若节点已存在于 `BossHitNodeParticleVfxController` 人工绑定，则粒子表现优先并排除该节点的固定拖尾。
- 拖尾与直刺保持独立生命周期：`BossAttackExecutor` 在 HitNode 整个激活窗口按 SourcePart 持续采样并聚合同帧采样器；`BossHitNodeParticleVfxController` 仍由人工 Timeline / HitNode 绑定，只在首帧捕获 SpawnAnchor 与 Boss 水平正前方或挂点朝向，生成无父节点世界实例，生命周期结束后销毁。攻击提前结束只立即关闭拖尾，不中断已生成直刺。
- Boss 命中接触反馈必须以真实结算结果为准：`Projectile_Hit_1.prefab` 只在 `PlayerCombatReceiver.ReceiveHit()` 后由 `CombatFeedbackPlayer.BossHit` 播放，不能由 HitNode 窗口本身或出手 VFX 触发；命中亮度 pulse 只提高绑定 Light 的表现强度，不改变战斗语义。
- `Raven_MoveCombo` 作为近中距离侧移三连普通攻击进入 ActionSet；它复用普通 `Attack` 类型、Combat Timeline HitNode、MotionWarpProfile CodeDrivenWarped，其 Weapon HitNode 固定使用武器 `SlashTrailVFX`，不新增特殊提示攻击、抓取、远程剑气或新执行器。`Raven_MoveChainCombo` 已进入 ActionSet，但只允许 Phase2 / Desperation 低频选择：压力成本高、压力上限低、最近 3 次不可重复，结束后强制 tempo reset。
- `Raven_ChaseGrab` 与 `Raven_SlashCombo` 作为黄光不可格挡攻击进入 ActionSet，但仍复用 `BossActionKind.Attack`、BossAttack Timeline、MotionWarpProfile 和 BossCombatSystem；不新增抓取执行器、蓝光 Grab、同步动画或新的 Combat 字段。
- 黄光不可格挡语义只由 HitNode 布尔位表达：`CanBeGuarded=false / CanBePerfectGuarded=false / CanBePerfectEvaded=true`。该类 HitNode 不产生 GuardHit / PerfectGuard，不奖励 PerfectGuard BetaEnergy，不播放 PerfectGuard VFX / SFX，也不触发 Boss PerfectGuardStagger；PerfectEvade 仍可成立。
- 黄光预警是表现层 cue：`BossYellowUnblockableCueVfxController` 按 AttackId + elapsed 播放 `FX_Boss_YellowUnblockableCue`，不触发 `Projectile_Hit_1`，不影响命中结算、BossReactionGate、MotionWarp 或 ActionSet 选择。
