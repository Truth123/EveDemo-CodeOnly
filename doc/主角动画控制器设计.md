# 主角动画控制器设计

本文档是 `Assets/Animator/Eve.controller` 的维护契约，用于约束玩家 Gameplay 状态机、`PlayerAnimationBridge` 和 Animator Controller 的分工。后续新增动画时，必须同步更新本文件、代码映射和 Play Mode 验证用例。

参考：

- Unity Animation State Machine: https://docs.unity3d.com/Manual/AnimationStateMachines.html
- Unity Sub-State Machines: https://docs.unity3d.com/Manual/NestedStateMachines.html
- Unity Animation Transitions: https://docs.unity3d.com/Manual/class-Transition.html
- Unity Animator.CrossFadeInFixedTime: https://docs.unity3d.com/ScriptReference/Animator.CrossFadeInFixedTime.html
- Unreal Animation Montage: https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-montage-in-unreal-engine

## 1. 控制原则

Gameplay 状态机是唯一战斗真相。Animator 只负责播放姿态、混合和视觉过渡，不承载伤害、无敌、判定窗口、资源消耗、派生规则或死亡判定。

稳定主流程由 Animator 转场维护：

- Locomotion：Idle / Run / LockOn 8Dir。
- Attack：Light / Heavy 连招入口与回 Locomotion。
- Normal Evade：普通闪避入口与回 Locomotion。
- Guard：Guard Start / Loop / Walk Start / Walk Loop / Walk End / End；移动中进入防御时 Guard Start 可快速混合到 Guard Walk，移动中松开防御可直接回 Locomotion。
- Skill：Skill1 入口与回 Locomotion。
- 动作结束直接进入 `SM_Locomotion`，由 Entry 条件选择具体 Idle / Move 目标动画。

事件型战斗反应用代码 `Animator.CrossFadeInFixedTime` 触发，所有混合时长与起播偏移都以秒为单位：

- PerfectEvade。
- HitReaction。
- GuardHit。
- PerfectGuard。
- Knockdown。
- Dead。

攻击主流程仍由 Animator 转场维护。ResetWindow 内重新进入同一个起手节点时，`L1 -> L1` 和 `H1 -> H1` 的 Animator 参数没有变化，可能无法重播同一状态；此时由 `PlayerAnimationBridge` 基于新的 `CurrentAttackInstanceId` 对 `Anim_Attack_L1 / Anim_Attack_H1` 执行极短 `CrossFade` 并从 0 起播。Attack 后摇末段的移动取消不新增动画参数，Gameplay 直接切到 `Locomotion`，再由现有 `SM_Locomotion` Entry 选择真实移动动画。

分开控制的原因：

- 稳定循环和常规动作需要 Animator 图可视化，便于检查入口、退出、Blend Tree 和循环。
- 受击、完美闪避、完美防御、死亡等事件需要按 gameplay 判定即时抢占，使用代码触发更可控。
- Guard 释放不再由 `GuardReleased` 瞬时事件驱动；Animator 只读取 `PlayerState / PlayerStatePhase / IsGuardReentry / IsGuardWalking` 等稳定状态信号。
- 连续 PerfectGuard 不新增 Animator 参数；代码通过 `GuardReactionRequestVersion` 递增让同一个 PerfectGuard 动画可重复 `CrossFade`。

## 2. Animator 拓扑

`Base Layer` 只保留子状态机结构，不再使用无 Motion 的返回中转状态。

| 子状态机            | 内容                                              | 默认状态                     | 进入来源                                                   |
| --------------- | ----------------------------------------------- | ------------------------ | ------------------------------------------------------ |
| `SM_Locomotion` | Idle、自由移动、战斗移动、锁定 8 向移动                         | `Anim_Idle_Normal`       | 默认状态、动作结束返回                                            |
| `SM_Attack`     | 轻/重攻击连招                                         | `Anim_Attack_L1`         | `AnyState` 根据 `PlayerState/AttackInputType/ComboIndex` |
| `SM_Evade`      | 普通闪避、完美闪避                                       | `BT_Evade_LockOn_8Dir`   | 普通闪避走 `AnyState`，完美闪避走代码 CrossFade                     |
| `SM_Guard`      | Guard Start/Loop/Walk/End、GuardHit、PerfectGuard | `Anim_Guard_Start`       | Guard 主流程走 `AnyState` 和本地转场，防御反应走代码 CrossFade          |
| `SM_Reaction`   | HitReaction、Knockdown、Dead                      | `Anim_HitReaction_Light` | 受击/击倒/死亡只走代码 CrossFade，不保留 `AnyState` 兜底                |
| `SM_Skill`      | Skill1                                          | `Anim_Skill_1`           | `AnyState` 根据 `PlayerState == Skill`                   |

动作状态结束时直接转入 `SM_Locomotion` 子状态机。`SM_Locomotion` 的 Entry 条件根据 `PlayerState / IsLockOn / IsInCombat` 选择真实目标动画，避免先切到无 Motion 空状态导致瞬切。

`SM_Locomotion` Entry 条件：

| 条件                                                      | 目标                    |
| ------------------------------------------------------- | --------------------- |
| `PlayerState == Idle && !IsLockOn && !IsInCombat`       | `Anim_Idle_Normal`    |
| `PlayerState == Idle && !IsLockOn && IsInCombat`        | `Anim_Idle_Battle`    |
| `PlayerState == Idle && IsLockOn`                       | `Anim_Idle_LockOn`    |
| `PlayerState == Locomotion && !IsLockOn && !IsInCombat` | `Anim_Move_Run`       |
| `PlayerState == Locomotion && !IsLockOn && IsInCombat`  | `Anim_Move_BattleRun` |
| `PlayerState == Locomotion && IsLockOn`                 | `BT_LockOn_Run_8Dir`  |

## 2.1 Root Motion 接入边界

玩家 Animator 的 `applyRootMotion` 在场景 / Prefab 中固定开启，仅用于触发 `PlayerRootMotionRelay.OnAnimatorMove()`。运行时不通过代码反复切换 `applyRootMotion`。

Root Motion 只作为 Light / Heavy Attack 的位移来源：

1. `PlayerRootMotionRelay` 读取 `animator.deltaPosition / deltaRotation`。
2. Relay 默认忽略垂直 Root Motion 和 Root Motion rotation。
3. Relay 把水平 delta 交给 `PlayerMovementMotor.HandleRootMotion(...)`。
4. `PlayerMovementMotor` 只在 `PlayerState == Attack` 时消费 Root Motion，并通过 `CharacterController.Move()` 执行。
5. 非 Attack 状态收到 Root Motion 时丢弃，避免 Locomotion、Guard、Evade、Reaction 被攻击动画残余位移推走。

Skill 动画不依赖 Root Motion，使用 `PlayerActionMotionProfile.Skill1Forward` 的代码位移；Evade、PerfectEvade、HitReaction、Knockdown 继续使用代码动作位移。

## 2.2 可编辑动画与马尾姿态

- `Eve.controller` 的正式 Motion 统一引用 `Assets/Animator/EveAuthored/*.anim`，不直接引用 `Assets/ThirtPartyModel/EveAnimation` 中的 FBX 子 Clip。
- 69 个唯一副本保持源动画的长度、帧率、事件、Root Motion 与非头发曲线；Controller 的 41 个直接状态和 5 个 BlendTree/31 个 Motion 槽位已全部重映射。
- `Ab-TL-HairB01～09` 的局部旋转按动画帧保存动作相关的向下贴背基础轮廓。`PlayerHairSecondaryMotionController` 在 Animator 求值后的 `LateUpdate` 读取该姿态，保持 B01 完全服从动画，并从 B02 到 B09 渐进叠加高阻尼、低惯性弹簧与重力。
- 运行时先把动画链投影为“碰撞安全动画目标”，再使用 `4.0Hz / 阻尼0.86 / 惯性0.20 / 重力1.15` 求解；头、肩、背、胸腹、骨盆和双腿仅使用不进入 Unity Physics 的数学代理体。去穿透位移不写入速度，接触会移除向内法向速度，深接触直接清零速度；上背以下代理还会移除向上修正分量，避免动画原始姿态嵌入身体时被腰髋端帽向上托起或向外弹飞。
- B02～B09 动态权重由 `0.12` 递增到 `0.94`。Knockdown / Dead 的动态权重为 0，由动画轮廓主导但继续执行碰撞安全修正；Attack / Skill / HitReaction 为 0.85、Evade 为 0.65，其余常态为 1.0，并在 0.18 秒内渐变。暂停、Animator 重启或角色位置/旋转突变时冻结或无速度重置。
- 后续手工调整马尾时只编辑 `EveAuthored` 副本，不修改第三方 FBX 源；不应借头发曲线改变身体、Root Motion、战斗窗口或 Animation Event。

## 5. 代码 CrossFade 表

`PlayerAnimationBridge` 对以下事件型状态执行固定秒数 `CrossFadeInFixedTime`。重复起手、PerfectEvade、战斗 Reaction 的混合时间分别为 `0.02s / 0.10s / 0.10s`，PerfectEvade 最大固定起播偏移为 `0.125s`。代码优先解析子状态机路径，例如 `Base Layer.SM_Reaction.Anim_HitReaction_F`；若控制器尚未迁移，则回退到旧根层路径，例如 `Base Layer.Anim_HitReaction_F`。

| 事件状态         | 子状态机          | 代码触发                              | 动画状态                                                         | 退出                                                                |
| ------------ | ------------- | --------------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------------- |
| 重复起手攻击       | `SM_Attack`   | `CrossFadeRepeatedStarterAttackIfNeeded` | `Anim_Attack_L1`、`Anim_Attack_H1`                              | 仅限 `L1 -> L1` / `H1 -> H1`，之后继续由 Attack 主流程和 Animator 转场控制          |
| PerfectEvade | `SM_Evade`    | `CrossFadePerfectEvadeIfNeeded`   | `Anim_PerfectEvade_F/B/L/R`                                  | `PlayerState < Evade` 到 `SM_Locomotion`                           |
| HitReaction  | `SM_Reaction` | `CrossFadeCombatReactionIfNeeded` | `Anim_HitReaction_F/B/L/R`，fallback `Anim_HitReaction_Light` | ExitTime 或 `PlayerState < Evade` 到 `SM_Locomotion`                |
| GuardHit     | `SM_Guard`    | `CrossFadeCombatReactionIfNeeded` | `Anim_Guard_Hit_Back/Left/Right`                             | ExitTime 到 `GuardLoop`；若代码已进入 Release，由 `AnyState -> GuardEnd` 接管 |
| PerfectGuard | `SM_Guard`    | `CrossFadeCombatReactionIfNeeded` | `Anim_PerfectGuard_L/R`                                      | ExitTime 到 `GuardLoop`；若代码已进入 Release，由 `AnyState -> GuardEnd` 接管；链式 PerfectGuard 成功时通过新的 `GuardReactionRequestVersion` 重播 |
| Knockdown    | `SM_Reaction` | `CrossFadeCombatReactionIfNeeded` | `Anim_Knockdown_Start_B/F`、`Loop`、`End`                      | 阶段变化或回 `SM_Locomotion`                                            |
| Dead         | `SM_Reaction` | `CrossFadeCombatReactionIfNeeded` | `Anim_Dead`、`Anim_Dead_Down_Start/Loop`                      | 终止状态，不自然返回                                                        |

## 6. 新动画接入 Checklist

1. 明确动画属于稳定主流程还是事件型反应。
2. 稳定主流程优先放入对应子状态机，并用 `PlayerState/PlayerStatePhase` 等稳定参数建入口。
3. 事件型反应必须在 `PlayerAnimationBridge` 中补齐子状态机路径和根路径 fallback。
4. 不允许使用瞬时输入的反条件表达持续状态；Guard 释放和回防御必须由 `PlayerStatePhase`、`IsGuardReentry` 等稳定状态参数表达。
5. 每个新状态必须在本文档写清入口、退出、是否循环和允许打断规则。
6. Play Mode 至少覆盖相邻状态：进入、自然退出、取消窗口、受击/死亡抢占、回 Locomotion。

## 7. 当前重点回归

- 短按 Guard：`GuardStart -> GuardEnd -> SM_Locomotion`，不能回跳 `GuardLoop`。
- 长按 Guard：`GuardStart -> GuardLoop`，松开后 `GuardEnd`。
- GuardHit / PerfectGuard 后继续按住：反应动画结束回 `GuardLoop`。
- GuardHit / PerfectGuard 期间松开：代码进入 Release，Animator 由 `AnyState -> GuardEnd` 接管。
- PerfectGuard 反应期间重新按下 Guard 后，若 ChainWindow 内再次成功 PerfectGuard，同一个 `Anim_PerfectGuard_L/R` 必须能被 `CrossFade` 重播。
- GuardRelease 中重新按下 Guard：Gameplay 重新进入 GuardStart 并开启 PerfectGuard / Block 时间轴，Animator 通过 `IsGuardReentry` 从 GuardEnd 快速回 GuardLoop / GuardWalk。
- 移动中按住 Guard：Guard Start 可在不改变 PerfectGuard / Block 时间窗的前提下快速到对应 Guard Walk Start，避免站桩滑步。
- GuardLoop 中移动：按方向播放 Guard Walk Start，持续时进入 `BT_Guard_Walk_2D`，停止移动但继续防御时播放对应 End 后回 GuardLoop。
- 移动中松开 Guard：状态机直接回 `Locomotion`，Animator 从 GuardStart / GuardLoop / GuardWalk / GuardEnd 快速回 `SM_Locomotion`，避免播放站桩 GuardEnd 滑步。
- 普通 Evade 不应抢 PerfectEvade；PerfectEvade 由代码 CrossFade 覆盖普通闪避剩余动画。
- Attack 后摇末段按住移动：若没有触发 Evade / Skill / Combo / AttackRestart / Guard，应直接回 `SM_Locomotion` 并进入对应移动动画。
- 受击、击倒、死亡 CrossFade 不应因状态迁入子状态机而找不到目标状态。
