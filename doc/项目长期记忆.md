## 1. 项目定位

Project EVE Demo 是用于求职作品演示的 Unity 3D 战斗系统项目。

核心目标是制作一套聚焦主角与渡鸦风格 Boss 战斗体验的动作战斗原型，重点展示：

- 第三人称移动、自由视角和锁定视角。
- 玩家战斗状态机。
- Light / Heavy attack combo。
- Evade / Perfect Evade。
- Guard / Perfect Guard。
- Skill、HitReaction、Knockdown、Recover、Dead。
- Boss AI、Hitbox / Hurtbox、战斗镜头、UI、VFX、SFX。

明确不优先开发：

- 大型探索场景。
- 背包、任务、对话、商店。
- 非战斗向复杂 UI。
- 与 Boss 战斗演示无关的大型系统。

## 6. 重要设计决策

- 状态机采用顶层状态拆分，状态间通过 `PlayerStateContext` 共享输入、资源、窗口和运行时状态。
- 输入事件进入状态机前形成快照，攻击、闪避、技能等可通过输入缓存跨窗口消费。
- Guard 是即时按下 + Hold 保持输入，不进入普通缓存；在允许窗口内读取 `GuardPressed || GuardHeld` 即时进入 Guard，释放由 `GuardHeld=false` 推导。
- 攻击窗口由 `AttackWindowSet` 管理，默认窗口规则必须与 Attack 需求文档保持一致。
- 攻击数据由 `AttackDefinition` 与 `PlayerAttackCatalog` 表达，避免把连段结构硬编码到状态判断中。
- 当前阶段优先可读、可调、可验证，不做过度抽象。
- 锁定移动使用 `MoveX / MoveY` 驱动 `BT_LockOn_Run_8Dir` Blend Tree。
- 锁定视角闪避使用进入状态时锁存的 `ActionMoveX / ActionMoveY` 驱动八方向 Blend Tree，避免闪避动画播放中途随输入变化漂移。
- 自由视角闪避只使用前后两个离散动画状态：有移动输入时锁存相机相对世界方向，角色转向后播放前闪；无移动输入时保持朝向并播放后闪。
- Perfect Evade 测试动画不使用 Blend Tree，四个方向动画差异较大，当前只保留离散预接状态。

## 7. 已知需求规则

攻击与窗口系统当前规则：

- Active 阶段开始开启 Attack / Evade / Skill 缓存接收窗口，Active 结束关闭。
- ComboWindow 在 Recovery 阶段开启，一定时间后关闭。
- ComboWindow 内可以消费攻击缓存，也可以接收即时 Light / Heavy 输入进入下一连段。
- ComboWindow 关闭后，如果已经进入 ResetWindow，Light / Heavy 即时输入重新进入对应起手攻击。
- EvadeCancelWindow 和 SkillCancelWindow 在 Recovery 阶段开启并覆盖 ResetWindow，窗口内可消费缓存或响应即时输入。
- GuardCancelWindow 在 Recovery 阶段开启并覆盖 ResetWindow，窗口内直接读取 `GuardPressed || GuardHeld` 进入 Guard。

动画测试接入当前规则：

- `Eve.controller` 位于 `Assets/Animator/Eve.controller`。
- `CH_P_EVE_51/Animator` 场景对象使用该控制器。
- LockOnRun 使用八方向原始动画 Blend Tree。
- Evade 使用自由视角前后离散状态和锁定八方向闪避 Blend Tree；旧自由闪避 `BT_Evade_Free` 状态已删除。
- 自由视角闪避方向在进入 Evade 后锁存为 `ActionWorldDirection`，避免闪避过程中旋转相机导致朝向漂移。
- `Eve.controller` 已废弃无 Motion 的 `Anim_ReturnToLocomotion` 中转站，动作退出直接进入 `SM_Locomotion`，由 Locomotion Entry 条件选择真实 Idle / Move 状态。
- Guard 释放由 `GuardHeld=false` 推导，Animator 使用 `PlayerStatePhase` 和 `IsGuardReentry` 同步 GuardEnd / Release 重入，不再使用 `GuardReleased` 驱动 Guard 主流程。
- 方向类动作和普通动作状态均已配置返回 Idle / Move 的显式转场，避免循环动画无法退出。
- Perfect Evade 使用 Evade 内部动画模式，不新增顶层状态；触发后通过 `IsPerfectEvadeActive` 和 `PerfectEvadeDirection` 切到四方向离散动画，不重置 Evade 时间轴。
- 第 6 阶段采用武器 Trigger Collider 方案，不使用代码 OverlapBox 作为攻击判定主路径。
- 场景 Boss 对象固定为 `RavenMonster_Mesh`，其上挂载 `CombatResourceComponent` 和 `CombatHurtbox` 作为当前 Boss Hurtbox 测试目标。
- 玩家武器测试对象为 `CH_W_Sword_01_Mesh`，其上挂载 `PlayerWeaponHitbox`、Trigger `BoxCollider` 和 kinematic `Rigidbody`，保证 Trigger 事件可以触发。
- `PlayerAttackState` 每次进入新攻击节点时写入当前攻击实例 ID、攻击类型、伤害和削韧数据；同一攻击实例对同一 Hurtbox 只命中一次。
- 第 8 阶段 Boss AI 需求设计入口已确定：第一版只实现 Raven 风格核心小循环，不完整复刻全招式。
- Boss 攻击数据采用 `BossAttackDefinition -> BossAttackHitNode` 结构：整招负责动画、角度、冷却和恢复；HitNode 负责命中窗口、部位、伤害、防御/完美防御/完美闪避语义。
- Boss 出招距离范围统一由 `BossMotionWarpProfile` 的 `BossAttackSelectionProfile.MinStartDistance / MaxStartDistance` 维护，不再在 `BossAttackDefinition` 中重复保存。
- Boss 命中去重粒度为 `AttackInstanceId + HitNodeId + TargetHurtbox`，避免同一 HitNode 持续接触重复结算，同时允许多段连击逐段命中。

# 2026-06-23 阶段状态补充：Combat Timeline 总时长改为帧模型

- Combat Timeline 动作总时长不再以独立秒值作为编辑器真相；`CombatTimelineActionAsset.TotalDuration` 改为由 `TotalFrames / FrameRate` 派生。
- 旧资产保留 `totalDuration` 作为迁移来源；当 `totalFrames <= 0` 时按当前 `FrameRate` 将旧秒值向上取整为总帧数，避免旧窗口被截短。
- Combat Timeline Editor 的 Asset Inspector 增加 `Total Frames`，Seconds 模式下编辑 Duration 也会向上取整转换为帧数，避免 H1 这类 `3.33s` 与 `80f / 24fps = 3.3333333s` 分叉。
- 修改 FrameRate 时默认保持 Total Frames 不变，不隐式重采样已有 clip；如果 clip 秒值因此越过新总时长，Validation 会按帧显示越界信息。
- Timeline Validation 继续严格限制非 Animation Preview clip 超出动作总时长，但错误信息会显示 clip 终点帧和动作总帧数，便于定位帧/秒混用问题。
