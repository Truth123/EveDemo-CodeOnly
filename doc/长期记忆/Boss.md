## 关键规则

- 第一版 Raven Boss 只实现核心小循环，不完整复刻所有招式。
- HitNode 负责伤害、防御、完美防御、完美闪避、反制和击倒语义。
- Boss 命中去重粒度为 `AttackInstanceId + HitNodeId + Target`；Target 优先取 `CombatHurtbox`，缺 Hurtbox 时取 `PlayerCombatReceiver`。
- PerfectGuard 可按 HitNode 配置触发 Boss 反制硬直。
- Skill1 前两段是 `DamageOnly`，只扣血不刷新 Boss 反应；第三段可击倒 Boss。第三段是否真正进入 Knockdown 由当前状态 Timeline 的 `BossReactionGateWindow` 决定。没有匹配 Allow gate 时只扣血不刷新反应；Block gate 可在同时间段阻止 Skill Knockdown，且优先于 Allow gate。
- Boss 是否被 Light / Heavy / Skill 打断不再由状态名硬编码；必须由当前状态 Timeline 的 `BossReactionGateWindow` 决定。不要恢复旧 `CombatInterruptWindowClip` 或 `SkillInterruptArmor` gate 路径。
- Boss 锁定朝向不等于全状态追踪：`Idle / Approach / Strafe` 可持续面向玩家，`Attack / Recovery / HitStagger / Knockdown` 不由 Actor 级通用朝向覆盖；玩家侧闪导致 Boss 承诺段挥空是合理结果。
- Boss 攻击期位移落点和面朝向是两条规则：landing target 用于 MotionWarp / CodeMove，facing target 用于旋转；`FollowTarget=false` 的窗口锁定窗口开始时的玩家位置，`FollowTarget=true` 才每帧跟随玩家。
- Boss 动作位移不被玩家 target 身体硬阻挡；玩家与 Boss 的最低身体距离由玩家侧软互斥维护。Boss 身体接触玩家不造成伤害，命中仍只由 Boss Hitbox / HitNode / PlayerCombatReceiver 链路决定。
- BossAttack / BossReaction Timeline 不再配置 Armor 轨；Boss 受击门控统一使用 `Boss Gate` 轨。
- Boss HitStagger 的普通攻击刷新还受 `BossDecisionMemory` 连续受击预算限制；Gate 允许只代表当前时间点可刷新，预算耗尽后后续普通 HitReaction 只扣血不刷新状态，让 Boss 能推进到 `Reaction_CanReturn` 起点并由 Brain 选择压力响应。StateMachine 不再因 HitStagger 超过反应总时长而直接切 Strafe。
- Boss 状态切换理由必须在 `BossActor` 的状态切换请求层显式表达；生产代码不得从普通 Tick、Brain、Reaction 或 Action 分支直接绕过请求层调用最低层 `CommitStateTransition()`。同状态 Reaction 刷新只重置 `StateElapsed`，不触发状态进入副作用或默认状态动画。
- Boss 主动进攻节奏由 `BossDecisionMemory` 记录，并由 `BossBrain / BossActionSelector` 只读消费。Attack 成功启动会增加 `tempoPressure`、连续攻击计数和最近 3 个动作；压力过高、连续 Attack 达上限或动作要求 `MustEnterNeutral` 后，下一次非承诺决策必须先提交至少 `0.3s` 的 `Approach / Strafe`，期间禁止出招。
- Boss 可读取玩家已经进入的公开状态和短期历史，但不能读取当前帧原始输入。玩家战术快照当前只保留状态/持续时间、频繁防御和持续后退；正式决策把玩家 Knockdown 作为强制中立条件，用受击状态暂停压力衰减，并把频繁防御 / 持续后退用于 Special / GapClose 池偏好及中立选择。
- Boss 选招在硬过滤后对全部正分合格候选做加权随机，不再截断 Top 3；测试可注入确定性随机源。
- Raven 软阶段只影响选招资格和权重，不是新状态机：Phase1 为 100% - 60% HP，Phase2 为 60% - 25% HP，Desperation 为 25% HP 以下。`Raven_MoveChainCombo` 只允许 Phase2 / Desperation，压力成本高、压力上限低、最近 3 次不可重复，结束后强制 tempo reset；不要再把它记录为 ActionSet 默认禁用招式。
- RootMotionWarped 使用窗口级 Root Motion 预算，不按单帧误差闭环。
- `BossMotionWarpProfile` 是 Boss 位移模式、出招距离、空间预筛选和动作位移参数的唯一配置源；缺 Profile 或缺 attack config 时记录错误并拒绝选择该招式。
- Boss Reaction 位移不新增独立 Profile；`HitStagger / Knockdown` 只通过 Reaction Timeline 的 `BossCodeMove` 引用 `BossMotionWarpProfile` 中的 action/window，缺配置时仍进入反应状态但不执行位移。
- Action / Reaction 的专用结束方法只能清理对应移动层；从 `HitStagger / Knockdown` 退出到 Attack、Idle、Reposition 等状态时只清理旧 Reaction 位移层，不得用全局 `StopAllMotion()` 清掉已经由新状态启动的 Action 位移层。
- Raven 持续拖尾默认读取 HitNode 已有 `SourcePart`：Weapon、LeftFoot、RightFoot 使用各自固定 `SlashTrailVFX`，其他来源不触发；已被直刺粒子控制器人工绑定的节点排除固定拖尾。同帧其他普通节点仍可启用自己的拖尾，两种表现都不作为伤害、距离、角度、PerfectGuard 或 BossReactionGate 的数据来源。
- `Raven_MoveCombo` 的 `MoveCombo_Orbit` 侧移窗口和 `Raven_MoveChainCombo` 的 Orbit / 闪现位移窗口不是 HitNode，不触发命中接触反馈或出手 VFX；其 Weapon / 足部 HitNode 是否启用固定刀光只服从 SourcePart。
- 黄光不可格挡不新增 Combat 字段或 Boss 专属 HitNode 类型：`CanBeGuarded=false / CanBePerfectGuarded=false / CanBePerfectEvaded=true` 是唯一战斗语义来源。反例：`Raven_ChaseGrab/ChaseGrab_Impact` 与 `Raven_SlashCombo/SlashCombo_YellowIai` 不能被 Guard / PerfectGuard 结算，也不能触发 PerfectGuard BetaEnergy、PerfectGuard VFX / SFX 或 Boss PerfectGuardStagger；它们只能被 Evade / PerfectEvade 避开。
- Raven 直刺攻击表现使用独立粒子 / VFX 资源，例如 `ChaseSlash_3_Effect.prefab`；`BossHitNodeParticleVfxController` 只在绑定 HitNode 首帧捕获挂点位置与选定方向并生成无父节点世界实例，不复用横斩 SmoothTrail 采样路径，攻击结束不提前销毁已生成实例。
- Boss 命中接触特效必须接在真实命中结算之后：`Projectile_Hit_1` 通过 `CombatFeedbackPlayer.BossHit` 播放，不能在 HitNode 激活或攻击出手时播放，避免挥空也出现命中特效。命中亮度 pulse 只作为表现层 Light 强度脉冲，不参与伤害、状态、HitNode 或位移。
