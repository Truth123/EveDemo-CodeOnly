
## 1. 设计目标

玩家战斗状态机用于复刻《剑星》风格 Boss 战中的主角战斗体验，重点支持高速近战攻防、连续攻击、闪避、完美闪避、格挡、完美格挡和受击、死亡反馈。  
本状态机优先保证战斗手感和可展示性，不追求完整商业游戏的所有动作分支。
本 Demo 玩家状态机仅覆盖 Boss 战所需的地面近战状态，不包含跳跃、攀爬、剧情交互、回血道具或背包等非核心功能。

系统目标：  
1. 保证玩家操作响应清晰。  
2. 支持近战连击、闪避取消、格挡、精准格挡等核心动作机制。  
3. 保证不同状态之间切换规则明确，避免输入冲突。  
4. 支持动画事件驱动攻击判定、无敌帧、连击窗口等战斗逻辑。  
5. 便于后续扩展技能、处决、空中攻击等功能。

### 2.2 混合位移源与单一移动出口

玩家移动出口统一由 `PlayerMovementMotor` 控制，所有水平位移最终都通过 `CharacterController.Move()` 执行。不同动作允许使用不同位移源：

1. Light / Heavy Attack 使用动画自带 Root Motion 作为攻击动作位移来源。
2. Skill 动画没有可用 Root Motion，使用 `PlayerActionMotionProfile` 配置的代码驱动动作位移。
3. Evade、PerfectEvade、HitReaction、Knockdown 继续使用代码驱动动作位移。
4. Locomotion 和 Guard Walk 继续由 `PlayerMovementMotor` 根据输入、相机和锁定目标计算速度。

Attack Root Motion 路径：

```text
Animator.OnAnimatorMove()
→ PlayerRootMotionRelay 读取 animator.deltaPosition / deltaRotation
→ PlayerMovementMotor.HandleRootMotion(...)
→ Attack 状态下消费水平 Root Motion
→ CharacterController.Move()
```

代码动作位移路径：

```text
PlayerState
→ PlayerStateContext.RequestActionMotion(...)
→ PlayerMovementMotor
→ PlayerActionMotionRuntime 按累计距离曲线计算水平 delta
→ CharacterController.Move()
```

职责边界：

1. `Animator.applyRootMotion` 在玩家 Animator 上固定开启，用于触发 `OnAnimatorMove()`；运行时不反复切换该属性。
2. `PlayerRootMotionRelay` 只捕获 Root Motion delta，不直接改 `Transform.position`。
3. `PlayerMovementMotor` 只在 `PlayerStateId.Attack` 消费 Root Motion；非 Attack 状态收到 Root Motion 会丢弃。
4. Root Motion 默认只使用水平位移，垂直位移和旋转仍由 Motor / 状态机管理。
5. `PlayerActionMotionProfile` 是 Skill、Evade、PerfectEvade、HitReaction、Knockdown 代码动作位移的调参入口。
6. `PlayerActionMotionRuntime` 只根据 MotionId、方向、距离、时长和累计距离曲线输出本帧水平 delta。
7. `PlayerMovementMotor` 是玩家唯一移动出口，统一执行普通移动、Root Motion 位移、动作位移、重力和 `CharacterController.Move()`。
8. 动作状态只提交位移请求或动画 Root Motion，不直接移动角色。
9. 动作位移期间清空普通水平速度，避免 locomotion 惯性叠加。
10. 受击 / 击倒 / Skill 代码位移遇到侧向碰撞时停止剩余水平动作位移，但状态时间轴不提前结束。

### 2.3 动画控制器维护契约

`Eve.controller` 的详细拓扑、参数语义、Animator 转场和代码 `CrossFade` 路径见 `doc/主角动画控制器设计.md`。

核心规则：

1. Gameplay 状态机是唯一战斗真相，Animator 只负责视觉播放、混合和过渡。
2. Locomotion、Attack、普通 Evade、Guard Start / Loop / Walk / End、Skill 等稳定主流程由 Animator 状态机和子状态机维护。
3. PerfectEvade、HitReaction、GuardHit、PerfectGuard、Knockdown、Dead 等事件型战斗反应用 `PlayerAnimationBridge` 代码 `CrossFade` 触发。
4. Guard 释放由 `GuardHeld=false` 推导；Animator 使用 `PlayerStatePhase` 和 `IsGuardReentry` 表达防御释放与重入，禁止使用瞬时输入表达持续防御。
5. 新增玩家动画必须同步更新 Animator、代码映射、`doc/主角动画控制器设计.md` 和 Play Mode 回归项。
6. Guard Walk 不新增顶层状态，只在 GuardLoop 中由 `PlayerMovementMotor` 执行慢走位移，Animator 播放方向 Start / 2D Loop / End。

### 2.4 状态代码维护约定

玩家每个具体顶层状态类必须独立成文件，文件名与类名一致，统一放在 `Assets/Runtime/Player/StateMachine/States/`，命名空间保持 `ProjectEVE.Player.States`。

当前约定：

1. `PlayerAttackState`、`PlayerEvadeState`、`PlayerGuardState`、`PlayerSkillState` 等具体状态均一状态一文件。
2. `PlayerStateBase` 是共享基类，不代表具体 gameplay 状态，可以独立成基类文件。
3. 新增具体状态时必须同步新增独立文件，并在 `PlayerStateMachine.RegisterStates()` 注册。
4. 不再新增 `PlayerCoreStates.cs` 这类集中状态文件，避免单文件过大导致维护和影响评估困难。

## 4. 状态优先级

  状态优先级用于解决多个状态切换条件在同一帧同时满足时的冲突问题。状态机每帧按照优先级从高到低判断，只允许最终进入一个顶层状态。  
### 4.1 受击解析优先级
  
当敌人攻击与玩家发生接触时，不直接进入 HitReaction 或 Knockdown，而是先进入 CombatHitResolver。  
CombatHitResolver 按以下顺序解析：  
1. 如果玩家 HP <= 0，进入 Dead。  
2. 如果玩家处于 Guard，且命中发生在 PerfectGuard，且攻击类型允许完美防御，进入 Guard.PerfectGuard。  
3. 如果玩家处于 Evade，且满足 PerfectEvade 与 NearMiss 条件，进入 Evade.PerfectEvade。  
4. 如果玩家处于 EvadeInvincibleWindow，忽略本次伤害。  
5. 如果玩家处于 Guard，且攻击类型允许普通防御，保持 Guard 并播放 GuardHit。  
6. 如果本次命中的 `CombatReactionIntent=Knockdown`，进入 Knockdown。  
7. 如果本次命中的 `CombatReactionIntent=HitReaction`，进入 HitReaction。

说明：

- Boss 对玩家的正式 HitNode 只表达 `HitReaction / Knockdown` 两类反应意图。
- `GuardHit / PerfectGuard / HitReaction / Knockdown / Dead` 是玩家防守窗口和资源结算后的输出结果。
- `CombatAttackType` 只保留玩家攻击来源通道语义，不再作为受击反应或 Boss 对玩家反应的推导来源。
- PerfectGuard 反应期间可通过重新按下 Guard 打开 `PerfectGuardChainWindow`，用于支持 `0.25s - 0.45s` 的 Boss 连续弹反；一直按住 Guard 不会自动连弹。

### 4.2 输入消费优先级

当同一帧多个玩家输入都满足消费条件时，按照以下顺序消费：
EvadeInput > SkillInput > Light/HeavyAttack > GuardPressed/GuardHeld > MoveInput
说明：
1. 允许窗口先决定某个输入是否具备消费资格。
2. 如果多个输入在同一帧都具备消费资格，再按照输入消费优先级选择。
3. LightAttack 和 HeavyAttack 属于同一 attack 槽，同槽以后输入覆盖前输入。
4. Guard 是即时按下 + Hold 保持输入，不进入普通缓存；允许窗口内 `GuardPressed || GuardHeld` 都可进入 Guard。
5. Locomotion 和 Idle 为最低优先级兜底状态。

**状态切换规则：**

```
1. 每帧状态机先处理强制状态，再处理输入状态。
2. 强制状态包括 Dead、Knockdown、HitReaction
3. 输入状态包括 Skill、Attack、Guard、Evade、Locomotion、Idle。
4. 同一帧只允许切换一次顶层状态。
5. LockOn 不改变顶层状态，只改变 ControlMode。
6. Move 和 Look 通常不触发强制状态切换，Move 只在 Idle / Locomotion 之间切换。
7. Attack、Skill、Evade、Guard 等动作状态结束时，根据 MoveMagnitude 决定回到 Locomotion 或 Idle。
8. 所有状态进入 Dead 时都必须清除输入缓存、关闭攻击判定、停止可取消窗口。
9. HitReaction、Knockdown、Dead 进入时清除所有缓存。
10. PerfectGuard 和 PerfectEvade 成功时，不进入 HitReaction。
```
