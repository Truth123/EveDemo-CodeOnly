## 2026-06-23：Combat Timeline 总时长改为 TotalFrames / FrameRate 派生

来源：用户指出只把 H1 的 `3.33` 改成 `3.3333333` 是硬编码补丁，换帧率后仍会复现秒值与帧值分叉。

影响模块：

- Combat Timeline Runtime 数据模型。
- Combat Timeline EditorWindow。
- Timeline Validation。
- Player / Boss Timeline 资产迁移。

旧规则或旧状态：

- `CombatTimelineActionAsset` 以独立 `totalDuration` 秒值作为动作总长。
- 编辑器 Frames 模式下 clip 时间会按 `frame / frameRate` 写入，可能与两位小数秒值总长不一致。
- H1 当前表现为 `totalDuration=3.33`，但多个末尾窗口为 `3.3333333`，Validation 报错；H2 因 `4s` 正好落在帧网格上不报错。

新规则：

- `CombatTimelineActionAsset` 新增 `totalFrames`，`TotalDuration` 由 `TotalFrames / FrameRate` 派生。
- 旧资产 `totalFrames <= 0` 时，按旧 `totalDuration * frameRate` 向上取整迁移为总帧数，避免旧资产窗口被迁移过程截短。
- Editor 中 `Total Frames` 成为总长的直接编辑入口；Seconds 模式下 Duration 输入也会向上取整转换为帧数，保证派生总长不短于输入秒值。
- 修改 FrameRate 默认保持 Total Frames 不变，不自动重采样已有 clip。
- Validation 保持严格越界规则，并在错误中显示 clip 终点帧与动作总帧数。

来源：用户要求 PlayerAttack 运行时窗口和默认导入源统一收敛到 Combat Timeline 资产数据，并保留 Phase 轨道运行时读取但只用于 `CurrentPhase`。

影响模块：

- PlayerAttack Timeline 资产与默认导入流程。
- `PlayerAttackCatalog`、`PlayerAttackState`、`AttackDefinition`、`AttackWindowSet`。

旧规则或旧状态：

- PlayerAttack 默认导入从 `Assets/Editor/ProjectEVE/CombatTimeline/Defaults/PlayerAttack/` 模板复制，不再从旧代码生成窗口数据，并保留目标 live 资产 GUID。
