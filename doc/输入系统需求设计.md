
## 1. 输入系统设计目标

本 Demo 的玩家输入系统用于管理 Boss 战中的所有玩家操作，包括移动、视角控制、锁定、攻击、闪避、完美闪避、奔跑、防御、完美防御和技能释放；
还管理 UI 界面相关的功能按键，主要就是暂停，然后在暂停的UI界面提供继续、战斗重置等功能
输入系统需要满足以下目标：

```
1. 支持自由第三人称视角和锁定视角两种操作模式。
2. 支持移动、攻击、闪避、防御、技能等核心战斗输入。
3. 支持轻攻击与重攻击组合形成连招树。
4. 支持短按闪避与长按闪避转奔跑, 并可以在闪避窗口内触发 PerfectEvade
5. 支持按住防御进入 Guard，并在命中窗口内触发 PerfectGuard。
6. 支持普通攻击最后一次按键长按，后续扩展为 BetaAttack。
7. 支持技能消耗特殊能量释放。
8. 支持输入缓存，提升连招和闪避手感。
9. 支持键鼠输入映射。
10. 输入系统只负责采集和解释输入，不直接决定最终状态切换，玩家状态机根据当前状态、状态优先级、资源条件和输入缓存，决定是否响应输入请求。
```

## 2. 输入定义

### 2.1 输入类型定义

- Press：按下触发
- Hold：按住持续生效
- Tap：短按触发（用于区分短按和长按）
- Vector2：方向持续输入

## 3. 状态输入响应

### 3.1 状态区间

| 概念                             | 作用                                  | 规则                                                                                                                                                                                                                                                                                  |
| ------------------------------ | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 招式起手区间<br>（CommitCancelWindow） | 出招准备，可以选择性地被闪避、技能或者防御打断，招式起手后通常无法打断 | Attack 状态进入后的前若干帧为 AttackCommitWindow，中文称为招式起手可取消区间。  <br>  <br>在该区间内，玩家可以用 Evade、Guard、Skill 取消当前攻击。  <br>一旦超过该区间，攻击进入 StartupLocked 阶段，直到指定取消窗口开启前，不能被普通输入主动取消。  <br>  <br>敌人攻击命中仍然可以根据霸体、无敌、防御状态打断玩家。                                                                            |
| 前摇阶段<br>(StartPhase)           | 动画前摇阶段                              |                                                                                                                                                                                                                                                                                     |
| 生效阶段<br>(ActivePhase)          | 动画生效阶段                              | 根据状态不同，Active Phase 含义不同<br>不同状态也可以再对生效阶段进行细分                                                                                                                                                                                                                                       |
| 后摇阶段<br>(RecoveryPhase)        | 动画后摇阶段                              |                                                                                                                                                                                                                                                                                     |
| 重置区间<br>（ResetWindow）          | 动作后摇期间允许动作取消的区间                     | 动作已经接近自然结束，允许玩家直接切换到下一个合法状态，而不需要等待角色先回到 Idle 或 Locomotion。<br>不同的状态允许的切换/取消动画不同，具体参考每个状态的设计                                                                                                                                                                                         |
| 输入缓存区间<br>（BufferWindow）       | 提前输入，等到可执行时自动触发                     | 缓存区间不固定等于 Recovery 阶段。  <br>每个状态、每个动作节点可以单独配置缓存开始时间、缓存结束时间和可缓存输入类型。  <br><br>如果某个输入在当前时间点不能立即执行，但当前动作后续存在对应的允许区间，则可以进入缓存。  <br>如果当前动作后续不存在对应允许区间，则该输入不进入缓存。                                                                                                                         |
| 连招允许区间<br>(ComboAllowWindow)   | 后摇中允许接下一段攻击的窗口                      | 鼓励继续进攻，可以穿插在不同时间段                                                                                                                                                                                                                                                                   |
| 闪避允许区间<br>(DodgeCancelWindow)  | 允许从当前动作切到闪避的窗口                      | 提供风险补救，可以穿插在不同时间段                                                                                                                                                                                                                                                                   |
| 防御允许区间<br>(GuardCancelWindow)  | 允许从当前动作切到防御的窗口                      | 提供保守转防，可以穿插在不同时间段<br>由于 Guard 是 Hold 类型输入，因此状态机在该窗口开启时不消费普通缓存，而是检测当前 GuardHeld 是否为 true。  <br>  <br>如果 GuardHeld=true，则立即进入 Guard。  <br>如果 GuardHeld=false，则不进入 Guard。  <br>  <br>GuardPressed 可以在当前状态允许立即防御时触发 Guard，但如果当前状态不允许防御，且玩家在 GuardCancelWindow 开启前已经松开，则不会在后续自动进入 Guard。 |
| 技能允许区间<br>(SkillCancelWindow)  | 允许从当前动作切到技能释放的窗口                    | 提供资源爆发，可以穿插在不同时间段                                                                                                                                                                                                                                                                   |

**允许区间 （CancelWindow）：** 
- 如果区间在缓存后且允许缓存，代表缓存后生效
- 如果区间在缓存前，代表可以立即打断当前动作。（一般是长前摇攻击前几帧允许取消，这个区间通常称之为招式起手）
- 如果区间在重置区间，代表正常动作转换
- 如果不存在该区间，代表完全不生效
- 如果多个按键都进入了缓存，还要考虑优先级和覆盖的问题
- 根据动作性质和收益，在不同的状态会有不同的允许窗口设计，连招允许区间、闪避允许区间、防御允许区间、技能允许区间可以重叠，也可以错开。详见每个状态的详细设计。
- 允许区间可以根据“命中/打空”产生不同的变化。比如 Attack 状态的允许区间可以区分 OnHit 与 OnWhiff。  OnHit 时开放更多派生窗口。  OnWhiff 时保留更长后摇，只允许较晚的 Evade / Guard / Reset。

## 4. Move 输入

| 项目     | 需求                                    |
| ------ | ------------------------------------- |
| 输入类型   | Vector2                               |
| 键鼠     | WASD                                  |
| 最小移动阈值 | 0.1                                   |
| 输出     | MoveDirection、MoveMagnitude、MoveAngle |

### 4.1 自由视角移动规则

1. Move 输入方向相对于当前相机方向计算。
	- W：朝相机前方移动
	- A：朝相机左方移动
	- S：朝相机后方移动
	- D：朝相机右方移动
2. 角色朝移动方向转向。
3. Look 输入控制相机旋转。
4. 角色移动方向不强制朝向 Boss。

### 4.2 锁定视角移动规则

1. 角色默认朝向锁定目标。
	- W：朝 Boss 前进
	- S：远离 Boss 后退
	- A：围绕 Boss 向左移动
	- D：围绕 Boss 向右移动
	- WA：左前移动
	- WD：右前移动
	- SA：左后移动
	- SD：右后移动
2. Move 输入转换为相对 Boss 的八方向移动。
3. Look 输入可微调镜头，但不完全自由旋转。
4. 移动动画使用 LockOnMove 八方向 Blend Tree。

> Move8Direction 根据 Move 输入角度计算。
> 当 MoveMagnitude < 0.1 时，不更新 Move8Direction，保留上一次方向。

### 5.1 相机设计

| 场景     | 相机方案                | 说明                                                                                                                                            |
| ------ | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 普通探索   | 第三人称自由跟随相机          | 1. Pivot 放在 Eve 上半身，而不是脚底<br>2. 鼠标上下改变 pitch<br>3. 相机沿球面/圆弧移动<br>4. 使用阻尼平滑<br>5. 低角度时略微拉近<br>6. 高角度时略微拉远<br>7. 用 SphereCast 防止相机穿墙            |
| 近战战斗   | 锁定相机 + 自动修正         | 在战斗中自动锁定敌人<br>根据技能或者特殊场景自动调整相机偏移<br>- 保证敌人攻击动作清楚可见；<br>- 方便玩家判断格挡、闪避、完美闪避时机；<br>- 让近战连招时不容易打空；<br>- 多敌人场景下帮助玩家维持主要目标。                         |
| Boss 战 | 锁定相机 + 读招构图         | 在战斗中自动锁定敌人<br>根据技能或者特殊场景自动调整相机偏移<br>- 拉出合适距离，让 Boss 全身或上半身动作可见；<br>- 锁定 Boss 时保持双方关系清楚；<br>- Boss 大招、突进、跳跃时相机自动调整；<br>- 让玩家能看到攻击前摇、闪光提示和位移方向。 |
| 特殊技能   | 电影化特写相机             |                                                                                                                                               |
| 剧情演出   | 预设 cinematic camera | 常见表现：<br>- 镜头切到特写；<br>- 相机沿路径移动；<br>- 角色和敌人动作进入固定构图；<br>- 技能结束后平滑切回战斗相机；<br>- 处决或大招时短暂接管玩家视角。<br>主要服务于视觉冲击力。                                  |
| 爆炸/重击  | camera shake 反馈     | 常见：<br>- 完美格挡；<br>- 爆炸；<br>- Boss 重击；<br>- 处决；<br>- Eve 被击中；<br>- 大型敌人落地。                                                                     |

快速动作位移镜头规则：

1. 玩家闪避、完美闪避、Skill 或其他快速位移不降低角色实际移动速度。
2. 战斗相机不直接使用玩家瞬时位置作为硬关注点，而是使用平滑关注点追随玩家上半身 pivot。
3. 普通移动时关注点保持快速响应；当关注点速度超过阈值时进入短暂缓冲，避免镜头被瞬间拖拽。
4. 快速位移缓冲不能使用单一速度阈值瞬间退出；必须带退出滞后、最短保持时间和关注点落后距离判断，避免闪避结束时从慢跟随突然切到高速追赶。
5. 关注点普通追赶也必须有最大速度上限，不能使用无限追赶速度；否则当 smoothed pivot 落后 raw pivot 时会产生速度突变和视觉震荡。
6. 普通 / 快速关注点平滑时间切换需要插值过渡，禁止从快速缓冲时间瞬间切回普通响应时间。
7. 场景重开或大距离传送时关注点直接对齐，避免镜头从旧位置长时间追赶。
8. CameraShake 只叠加最终相机位置，不反向影响关注点、锁定目标或玩家位移。

## 7. EvadeInput 输入

| 项目   | 需求              |
| ---- | --------------- |
| 输入名  | EvadeInput      |
| 键鼠   | Shift           |
| 输入类型 | Press / Hold    |
| 短按   | 触发 Evade        |
| 长按   | Evade 结束后进入冲刺奔跑 |
|      |                 |

- EvadeInput 同时承担闪避和奔跑功能。玩家按下 EvadeInput 时立即触发 Evade
- Evade 状态结束时，若 EvadeInput 还在持续按住，且 MoveMagnitude > 0.1，则进入 Locomotion 的冲刺奔跑 Sprint 子状态
- Evade 状态结束时，若 EvadeInput 还在持续按住，且 MoveMagnitude <= 0.1, 则无法进入奔跑状态，先回到Idle状态。回到Idle状态后，如果 EvadeInput 还处于长按状态，当 MoveMagnitude > 0.1 时，直接从 Idle 过渡到冲刺奔跑
- 允许在招式起手区间取消部分攻击

## 8. Attack 输入

| 项目       | 需求            |
| -------- | ------------- |
| 输入名      | LightAttack   |
| 键鼠       | 鼠标左键          |
| 输入类型     | Press / Hold  |
| Press 用途 | 轻攻击、轻攻击连招派生   |
| Hold 用途  | 预留 BetaAttack |

| 项目       | 需求                  |
| -------- | ------------------- |
| 输入名      | HeavyAttack         |
| 键鼠       | 鼠标右键                |
| 输入类型     | Press / Hold        |
| Press 用途 | 重攻击、重攻击连招派生         |
| Hold 用途  | 预留 BetaAttack 或蓄力攻击 |

LightAttack 和 HeavyAttack 共同驱动普通攻击连招系统。攻击输入只产生攻击请求，具体进入哪一段攻击由 ComboSystem 根据当前 ComboNode 和输入类型决定。当前不在 Attack 状态时，LightAttack 进入轻攻击起手，HeavyAttack 进入重攻击起手。当前处于 Attack 状态时，LightAttack 和 HeavyAttack 需要在 ComboWindow 内被消费，并进入下一 ComboNode。
LightAttack 和 HeavyAttack 均需要支持 Press / Hold 检测，为后续 BetaAttack 预留。BetaAttack 第一版不实现，但攻击输入系统需要能够识别 LightHold 和 HeavyHold。

## 9. GuardInput 输入

| 项目   | 需求         |
| ---- | ---------- |
| 输入名  | GuardInput |
| 键鼠   | E          |
| 输入类型 | Hold       |
| 按下   | 尝试进入 Guard |
| 按住   | 保持 Guard   |
| 松开   | 退出 Guard   |

- Guard 为 Hold 输入。玩家按下 Guard 时，如果当前状态允许防御，则进入 Guard。玩家持续按住 Guard 时保持防御状态。玩家松开 Guard 时退出 Guard。Guard 输入不进入缓存。
- PerfectGuard 不需要额外按键。它由 Guard 状态、敌人攻击命中时机和 PerfectGuardWindow 共同触发。输入系统需要记录 GuardPressedTime，用于状态机判断是否处于完美防御窗口。
- 允许在招式起手区间取消部分攻击

## 10. Skill1Input 输入

| 项目   | 需求           |
| ---- | ------------ |
| 输入名  | Skill1Input  |
| 键鼠   | 1            |

## 11. 输入缓存规则

输入缓存只用来优化用户角色操作，由角色每个状态进行单独管理。
通用规则逻辑：

```
加入缓存：当前不能执行，但当前状态明确允许稍后执行时。
清除缓存：过期、被消费、状态大变化、被新输入覆盖、发生互斥选择时。
消费缓存：进入对应动作允许窗口，并且该输入优先级最高时。
冲突处理：同类一般后输入覆盖，不同类按状态优先级。
```

### 11.1 总体结构

```
InputSystem
├─ RawInputHistory        原始输入历史，负责记录最近若干帧发生过什么按键变化，便于识别组合键、输入先后，便于处理“刚按下”和“持续按住”
├─ CommandRecognizer      指令识别器，
├─ GlobalCommandBuffer    全局候选指令缓存，可选
└─ CharacterState   
	└─ StateLocalBuffer    角色当前状态自己的缓存规则
```


### 11.2 缓存槽设计方式

分类槽缓存 + 状态本地缓存： 每个状态拥有自己的缓存配置，而不是所有状态共用一套规则。

**分类槽：**
- attack 槽：轻攻击 / 重攻击 / 派生攻击
- Evade 槽：闪避 / 完美闪避
- skill 槽：技能 1 / 技能 2 

**缓存配置规则：**
- 加入缓存的规则
- 缓存命令冲突的处理
- 消费缓存的规则
- 清除缓存的规则

默认规则：
```
同槽：后输入覆盖前输入
跨槽：保留，消费时按当前状态优先级
消费后：清除自身和冲突槽
进入大状态：按状态规则清理
每帧：清除过期缓存
每帧：最多消费一个主动作
```

注意过期时间、缓存区间和其他各区间的设计，避免缓存经过较长时间之后还能生效，会给玩家一种不灵敏的延迟感
